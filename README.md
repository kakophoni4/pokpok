# Клуб спортивного покера

Платформа для лиги живого спортивного покера **без денежных ставок**: расписание игр,
запись на турниры, ввод результатов, рейтинг сезона, личный кабинет и достижения.
Один и тот же React-код работает как сайт, как PWA (иконка на домашнем экране iPhone)
и как Telegram Mini App. Telegram-бот даёт упрощённый набор действий: посмотреть
расписание, записаться, узнать состав и рейтинг.

## Как это устроено

```
apps/
  api/            NestJS + Prisma: вся бизнес-логика и единственный доступ к БД
  web/            React + Vite: сайт, PWA и оболочка Telegram Mini App
  bot-telegram/   grammY: тонкий клиент того же публичного API
packages/
  contracts/      Zod-схемы: типы запросов, ответов и enum'ов для всех приложений
  rating/         Чистая математика рейтинга — без БД и без сети
```

Три принципа, из которых выросла эта структура:

**Бизнес-правила живут в одном месте.** Бот не обращается к базе и не знает про
лимиты мест или лист ожидания — он вызывает тот же `POST /api/tournaments/:id/register`,
что и кнопка на сайте. Поэтому бот физически не может разойтись с сайтом в поведении.

**Рейтинг — это журнал, а не число.** Каждое начисление пишется отдельной строкой в
`RatingEvent`: за какое место, в каком турнире, каким полем, кто внёс. Таблица
`UserSeasonStats` — только кэш, её можно удалить целиком и пересчитать из журнала.
Из этого следует то, что на практике важнее всего: **исправление результата — обычная
операция**. Администратор перезаписывает протокол, старые события турнира удаляются,
новые начисляются, статистика пересчитывается — в одной транзакции.

**Типы описаны один раз.** `packages/contracts` — источник истины для API, сайта и бота.
Enum'ы неизбежно дублируются в Prisma-схеме, поэтому есть тест, который падает, если
они разойдутся (`packages/contracts/src/enums.test.ts`).

### Стек

| Слой | Выбор | Почему |
| --- | --- | --- |
| API | NestJS 11 + Prisma 7 | Модули, DI и guard'ы дают предсказуемую структуру, когда правил доступа много |
| БД | PostgreSQL 17 | Транзакции с уровнем Serializable для конкурентной записи на последнее место |
| Фронтенд | React 19 + Vite + Tailwind 4 | Один код на сайт, PWA и Mini App |
| Данные на клиенте | TanStack Query | Кэш, инвалидация и повторные запросы без ручного состояния |
| Бот | grammY | Типизированный, лёгкий, хорошо живёт на long polling и на webhook |
| Валидация | Zod 4 | Одна схема даёт и рантайм-проверку, и TypeScript-тип |

### Как работает вход

Пароля нет вообще. Три пути, все ведут к одному аккаунту:

1. **Сайт** — Telegram Login Widget: Telegram подписывает данные, API проверяет
   HMAC-SHA256 своим токеном бота.
2. **Mini App** — `initData` из Telegram, проверяется тем же способом.
3. **Бот** — сервер-серверный обмен: бот предъявляет `INTERNAL_API_TOKEN` на
   `/api/auth/internal/provider-session` и получает обычную пользовательскую сессию.

Дальше — свои JWT: короткий access-токен в памяти и ротируемый refresh-токен в
httpOnly-cookie (в базе хранится только его SHA-256). Ник берётся из Telegram при
первом входе, менять его может только администратор.

## Быстрый старт

Нужны Node.js 22+, pnpm 10 и работающий PostgreSQL 17.

```bash
pnpm install

cp .env.example .env
# Заполните DATABASE_URL, JWT_SECRET и INTERNAL_API_TOKEN

pnpm db:migrate          # создать схему
pnpm db:seed             # демо-данные: сезон, 14 игроков, 6 прошедших и 4 будущих турнира

pnpm dev                 # API на :3000 и сайт на :5173
```

Откройте <http://localhost:5173>. Бота ещё нет, поэтому для входа используйте карточку
**«Локальная разработка»** на `/login` — вход по нику из демо-данных:

| Ник | Роль |
| --- | --- |
| `Ferz` | администратор |
| `Kate_AA` | организатор |
| `Sanya_River` | игрок |

Этот вход отключается сам при `NODE_ENV=production`.

### Проверка, что всё живо

```bash
pnpm test                # 59 тестов: рейтинг, схемы, авторизация, UI, форматирование бота
pnpm smoke               # 36 сквозных проверок против запущенного API
pnpm typecheck
```

`pnpm smoke` — самое полезное после изменений в API: он проходит реальный путь целиком,
включая запись на турнир, лист ожидания, повторную отправку результатов и обмен
Telegram-личности на сессию.

### Telegram-бот

```bash
# 1. Получите токен у @BotFather
# 2. В .env: TELEGRAM_BOT_TOKEN, TELEGRAM_BOT_USERNAME, VITE_TELEGRAM_BOT_USERNAME
pnpm dev:bot
```

Команды: `/schedule` (расписание с кнопками записи), `/rating`, `/me`, `/who`, `/help`.

Один и тот же `TELEGRAM_BOT_TOKEN` должен быть у API и у бота: API этим токеном
проверяет подписи Telegram.

## Рейтинг

Формула настраивается на уровне сезона (`Season.ratingConfig`) — менять код,
чтобы подкрутить начисления, не нужно:

| Параметр | Смысл |
| --- | --- |
| `baseParticipation` | очки за явку — приходить всегда выгоднее, чем пропустить |
| `placementWeight` | вес места |
| `fieldSizeWeight` | насколько сильнее ценится победа в большом поле |
| `itmShare` / `itmBonus` | доля призовой зоны и бонус за попадание в неё |
| `knockoutPoints` | очки за нокаут |
| `noShowPenalty` | штраф за неявку после записи |
| `bestOfCount` | сколько лучших результатов идёт в зачёт сезона (0 — все) |

Очки за место: `baseParticipation + placementWeight × доля_побеждённых × (1 + fieldSizeWeight × log-размер_поля)`,
всё умножается на коэффициент турнира (`ratingMultiplier`), плюс бонусы за призы и
нокауты. Логика целиком в `packages/rating` и покрыта тестами — её можно читать и
проверять, не поднимая базу.

Демо-сезон использует «10 лучших результатов», поэтому пропустить неделю не
катастрофа — это осознанное решение в пользу регулярных, а не всех подряд игроков.

## Установка на iPhone

Сайт — полноценное PWA. На iOS нет программного запроса установки, поэтому в Safari
показывается разовая подсказка: **Поделиться → «На экран „Домой“»**. После установки
приложение открывается без интерфейса браузера, с учётом «челки» и home-индикатора.
Подсказка не показывается ни внутри Telegram, ни если приложение уже установлено.

## Что дальше

Готово: API целиком, сайт со всеми разделами и админкой, Telegram-бот, PWA, сиды,
тесты и сквозные проверки.

Следующие шаги в порядке практической пользы:

1. **Вход через VK ID** (OAuth 2.1 + PKCE). Модель данных уже готова: `Identity`
   поддерживает несколько провайдеров на аккаунт, привязка второго провайдера
   реализована через одноразовый токен (`/api/auth/link/:provider`).
2. **VK-бот** на vk-io. Форматирование сообщений в `apps/bot-telegram/src/format.ts`
   специально сделано чистыми функциями — при выносе в `packages/bot-core`
   переиспользуется как есть.
3. **Уведомления** — воркер на BullMQ: напоминание за сутки и за час до турнира,
   сообщение при переходе из листа ожидания в основной состав. В схеме уже есть
   таблица `Outbox` под этот сценарий.
4. **Автоматические ачивки.** Правила уже описаны (`AchievementRule`: количество
   побед, число игр, топ-3, серия посещений, нокауты, место в сезоне) и хранятся
   вместе с ачивкой — осталось прогонять их после ввода результатов.
5. **Деплой**: docker-compose (API + Postgres + Caddy для TLS), раздача статики сайта
   тем же reverse proxy на `/`, а API на `/api` — то же разделение, что и в dev, поэтому
   cookie и CORS ведут себя одинаково.

## Заметки для эксплуатации

- **Персональные данные** храните на серверах в РФ (152-ФЗ). Из ПД тут только то, что
  отдаёт Telegram: id, имя, username, аватар.
- **Мобильные сторы.** Приложение не про деньги, и это должно быть видно: никаких
  ставок, вводов и выводов. Формулировка «спортивный покер, игра без денежных ставок»
  на видном месте — не косметика, а условие прохождения ревью.
- **Роли** иерархичны: `player` < `moderator` < `admin`. Организатор ведёт турниры и
  вносит результаты; смена ников, ролей и правка рейтинга вручную — только у админа.
  Все административные действия пишутся в `AuditLog`.
